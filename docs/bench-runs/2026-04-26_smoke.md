## The one real datapoint

```
task  tool  version  replicate  wall_s     peak_rss_mb  exit_code  correct  notes
T1    gfc   0.1.5    1          3152.21    3294.64      0                   fixture=chr22.biallelic.snps.filtered.vcf.gz
```

`gfc vcf-to-eigenstrat` on 1KG chr22 biallelic SNPs (~1.1 M sites × 2504
samples): **52 min wall, 3.3 GB peak RSS, 4 cores allocated.** Single rep, no
warm-up rep dropped.

EIGENSOFT `convertf` does this conversion in single-digit minutes on comparable
hardware. Treat the gap (≈10×) as a substantive performance issue in the gfc
converter, not harness noise.

## Findings (in priority order)

### 1. `gfc vcf-to-eigenstrat` is too slow to ship

3.3 GB RSS on a 200 MB compressed input strongly suggests the converter is
materialising the whole VCF (or a per-record list-of-lists) instead of
streaming. Profile target #1.

Suspects to check first:
- `pysam.VariantFile` iteration with default per-record allocations.
- String concatenation inside the genotype hot loop instead of
  `''.join(...)` or pre-allocated buffers.
- Per-record file flushes on the output side.
- Building intermediate Python lists of all genotypes before writing.

Profile recipe for tomorrow:
```bash
# subset the input first so the profile finishes in minutes, not an hour
bcftools view -r 22:16000000-17000000 \
  benchmarks/data/1kg/chr22.biallelic.snps.filtered.vcf.gz \
  -Oz -o /tmp/chr22.subset.vcf.gz
tabix -p vcf /tmp/chr22.subset.vcf.gz

python -m cProfile -o /tmp/gfc_t1.prof \
  $(which gfc) vcf-to-eigenstrat \
  --input-dir /tmp \
  --output-dir /tmp/gfc_t1_profile \
  --pattern chr22.subset.vcf.gz --force

python -c "import pstats; p=pstats.Stats('/tmp/gfc_t1.prof'); p.sort_stats('cumulative').print_stats(40)"
```

### 2. AGAT entry-point bug in `run_on_condor.sh:68`

`hardware.log` from this run shows:
```
benchmarks/condor/run_on_condor.sh: line 68: agat_sp_gff2gtf.pl: command not found
AGAT not installed
```

`agat=1.4.0` IS in the conda env (`command -v agat` resolves cleanly). AGAT 1.x
moved from script-per-task (`agat_sp_gff2gtf.pl`) to subcommand
(`agat sp gff2gtf`). T4 (`gff3_to_gtf`) will silently skip the AGAT competitor
unless `run_on_condor.sh:68` is updated.

Fix:
```bash
# old
agat_sp_gff2gtf.pl --version
# new (1.x)
agat sp gff2gtf --help | head -1   # or `agat --version` for the umbrella
```

Also audit `tasks/T4_gff3_to_gtf.sh` for the same pattern.

### 3. `orf_trans_all.fasta.gz` download fails during bootstrap

```
[get ] https://sgd-archive.yeastgenome.org/sequence/S288C_reference/orf_protein/orf_trans_all.fasta.gz
curl: (35) Recv failure: Connection reset by peer
```

This is the OrthoFinder reference dataset. T7 (`orthogroups`) will fail without
it. Two options:

- Pre-stage the file in `benchmarks/data/orthofinder/` and gitignore the heavy
  bits while keeping a tiny header check.
- Switch to a smaller two-species pair already in the Y1000+ slice
  (`saccharomyces_cerevisiae` + `kluyveromyces_lactis`) and drop the SGD
  dependency entirely.

The second is cleaner — keeps the benchmark self-contained on Y1000+.

### 4. `correct` column is empty

Stage 1 fairness commit dropped the broken T1/T6 baselines but did not add a
correctness check populating the `correct` column. Without it the benchmark
reports speed only, which is half the story (and the dangerous half — a tool
can be fast and wrong).

Per-task correctness check spec:
- T1 (vcf → eigenstrat): shasum `.geno + .snp + .ind` against EIGENSOFT
  `convertf` reference output.
- T2 (vcf → plink): byte-identical `.bed/.bim/.fam` against PLINK 1.9.
- T3 (fasta+gff → gbk): structural equivalence via `Bio.SeqIO` parse of both,
  compare feature counts and joined sequence shasum.
- T4 (gff3 → gtf): line-set equivalence after sort + canonical-attribute order.
- T5 (gff3 → bed12): byte-identical against `gff3ToBed12` from UCSC tools.
- T6 (hmmer tblout → tsv): byte-identical against pyhmmer reference parser
  (`benchmarks/refs/t6_pyhmmer.py`, already in repo).
- T7 (orthogroups → matrix): row-wise equivalence after canonical species
  ordering.
- T8 (pseudohaploid): byte-identical against the reference implementation.
